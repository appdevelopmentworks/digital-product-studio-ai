## 2. JTBD(Jobs-to-be-Done)

### 2.1 メイン JTBD

> 私は会議の録音を投げるだけで議事録を生成し、Slack / Teams で共有して、後から検索できる状態にしたい。

### 2.2 サブ JTBD

1. **要約品質の保証**: 重要な決定事項 / アクションアイテムを漏らさず抽出してほしい
2. **共有の即時性**: 会議終了後 30 分以内に議事録を共有したい
3. **検索可能性**: 「3 月の経営会議で人材戦略について話した内容は?」を検索で引きたい
4. **プライバシー**: 録音内容が学習データに使われない安心感

## 3. Value Hypothesis(価値仮説)

### 3.1 仮説本文

> AILEAP の日本語特化精度(Whisper + Claude のチューニング)+ 中堅企業ワークフロー特化により、既存サービス(Notta / tl;dv / Otter.ai)では満たせない以下を提供できる:
>
> 1. **日本語の会議要約品質**: 業界用語 / 社内用語の正確な認識
> 2. **中堅企業向けの即実用性**: 過剰な機能を削ぎ「録音→要約→共有」だけにフォーカス
> 3. **AILEAP の AI Native 運用ノウハウ**: プロンプトチューニング継続改善

### 3.2 検証条件

β版で以下が達成されれば PMF 成立と判断:

- 5 名以上のテストユーザー(Week 4 時点)
- 平均要約精度 4.0 / 5.0 以上(自己評価アンケート)
- 30 件以上の会議録音処理(Week 8 = 公開時時点)
- 30% 以上の継続利用率(月 1 回以上の利用)

---

## 4. Anti-Hypothesis(反仮説 / 棄却条件)

以下のいずれかが起きたら本案件は **pivot or kill**:

### 4.1 Hard kill 条件

1. β版申込み 50 名のうち実利用が 10 件未満(Week 4 時点)→ **関心度低い** → kill
2. 要約精度が 4.0/5.0 を継続的に下回る(2 週間連続)→ **品質が市場要求未達** → 1 ヶ月のチューニング後に再評価。改善しなければ kill
3. β版利用者が「中堅企業向け機能」より「個人向け機能」を強く要求 → **セグメント誤り** → pivot(個人向けにポジション変更)

### 4.2 Soft pivot 条件(kill ではなく方向修正)

1. 録音 → 要約完了率が 80% を下回る(技術的問題)→ **アーキテクチャ見直し** → Sprint 計画を変更
2. LLM API コストが想定の 2 倍を超える(月 10 万円超過)→ **コスト構造再考** → モデル切替 or 機能削減
3. ユーザーが「議事録 PDF」より「Slack 連携」を強く要求 → **優先機能の入替** → roadmap 改訂

## 5. MVP 範囲(Desired MVP Scope)

### 5.1 必須機能(本案件 v1.0 / β版で実装)

- 招待制ユーザー登録(magic link 認証)
- 録音アップロード(.mp3 / .m4a / .wav / 最大 1GB)
- 自動要約(Whisper + Claude)
- 議事録 PDF 出力
- 簡易な利用統計ダッシュボード(管理者用)
- 最小限のユーザー Web UI(録音アップロード + 議事録閲覧)

### 5.2 v1.5 で追加(本案件スコープ外)

- Slack / Teams 連携
- 議事録の意味検索(LP コピーで言及した機能)
- チーム / ワークスペース機能

### 5.3 v2.0 以降

- SSO
- API 公開(法人向け)
- 課金機能(正式版から)

## 6. 競合分析(GEO クエリ別)

| 競合 | 特徴 | 差別化軸 |
|---|---|---|

| tl;dv | 海外発・録画 + 要約 | 日本語精度で AILEAP 優位 |
| Otter.ai | 英語精度高い・SaaS 老舗 | 日本語では AILEAP 優位 |
| MeetGeek | AI 多機能 | 機能多すぎて中堅企業に過剰 / AILEAP は MVP 思想 |
| 国内競合複数 | 業界特化系 | AILEAP は中堅企業横断・業界依存しない |
